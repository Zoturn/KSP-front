# Proposal

**Frontend phase 1** — the first code in this repo. Runs in parallel with the backend's
`catalog-read-model` change rather than after it; see "What the contract blocks" below.

## Why

This repository contains documentation and conventions and **no application**: no
`package.json`, no `src/`, nothing runnable. Every frontend convention we have written —
tokens-first Tailwind, TanStack Query for all server state, a generated GraphQL client — is
currently a claim with nothing demonstrating it.

The useful thing to build first is not a product page. It is the **shell plus the contract
pipeline**: an app that runs, a design system with real tokens, and `graphql-codegen` actually
generating a typed hook from the backend's committed `schema.gql` and rendering its result.
That last part matters more than it looks — it proves the cross-repo contract end to end while
the contract is still one field wide and mistakes are cheap. If codegen is wired for the first
time against nine catalog types, any problem in the pipeline is tangled up with the catalog.

## What the contract blocks, and what it does not

The backend's committed `schema.gql` currently exposes exactly one field, `apiStatus: String!`.
`Product`, `Category` and `ProductImage` do not exist in the contract until the backend's
`catalog-read-model` change lands. That draws a hard line through frontend work:

**Not blocked — this change:** tooling and scaffold, Tailwind token layer, design-system
primitives, app shell and routing, TanStack Query provider and conventions, codegen wiring, and
one real vertical slice through the whole stack using `apiStatus`.

**Blocked — a later change:** product list, product detail, category navigation, and anything
else typed against catalog data.

**Explicitly rejected as a way around it:** hand-writing placeholder `Product`/`Category` types
so catalog components can be built now. That defeats the generated contract, and every such
type becomes rework the moment the real schema arrives. `frontend.md` already forbids
hand-written API types; this change does not create an exception.

## What Changes

- **Scaffold** Vite + React + TypeScript, with the repo's Node floor (`>= 24.9`, matching the
  backend) pinned in `engines` and `.nvmrc`.
- **Tailwind with a token layer** — colours, spacing, radii and typography defined once as
  design tokens and consumed through them, not as ad-hoc utility values scattered in markup.
- **Design-system primitives**: `Button`, `Input`, `Card`, `Spinner`, `Alert` — the smallest set
  the shell needs, each with tests and an explanation. No component library (MUI was raised and
  rejected; `config.yaml` records that).
- **App shell**: root layout, header/footer, routing, a 404 route, and an error boundary.
- **Explicit state components**: `Loading`, `Empty` and `ErrorState` as first-class shared
  components, because "an unhandled error state is a bug" is only enforceable if the pieces
  exist to handle it with.
- **TanStack Query** provider, with the query-key and cache conventions written down and
  demonstrated once.
- **`graphql-codegen`** reading `../ksp-backend/schema.gql` — the committed file, never a live
  URL — emitting into `src/api/generated/` (gitignored as build output, regenerated by script).
- **One vertical slice**: a status view that runs the generated `apiStatus` query against the
  running backend and renders loading, error and success states. Thin, but it exercises
  scaffold → tokens → primitives → query client → generated types → rendered output.
- **Vitest + React Testing Library**, with the first tests written alongside the primitives
  rather than after them.
- **Documentation fixes** this work exposes: `CLAUDE.md` still describes `api/` as holding an
  "axios instance & interceptors" (a REST leftover in a GraphQL-only project), points at
  `../.claude/rules/frontend.md` when those rules live in this repo, calls `schema.gql` "the
  backend spec", and states the HTTP-200 error rule without the parse/validation exception the
  backend verified.

No **BREAKING** changes — there is nothing yet to break.

## Non-goals

- **Any catalog UI.** Product list, detail, category tree. Blocked by the contract, above.
- **Auth, cart, checkout, account, admin.** Later phases, and auth needs the backend's Phase 5.
- **A component library or a CSS-in-JS runtime.** Tailwind and our own primitives.
- **Dark mode / theming beyond the token layer.** Tokens make it possible later; this change
  does not ship a second theme.
- **SSR, i18n, analytics, PWA.** None are asked for.
- **Visual regression or E2E (Playwright) testing.** Vitest + RTL only for now.
- **Deployment.** No hosting, CI or preview pipeline in this change.

## Capabilities

### New Capabilities

- `web-shell`: the application shell a visitor always sees and the states it must handle —
  routing to a page, an unknown URL, a failed render, and data that is loading, absent or
  broken — plus the design tokens and primitives those states are built from.
- `api-client-generation`: the typed GraphQL client is generated from the backend's committed
  schema rather than written, and a schema the client was not generated against must fail
  rather than silently drift.

### Modified Capabilities

None. This repo has no existing specs — `openspec/` was initialised by this change.

## Impact

**New files**: essentially the whole repo — `package.json`, Vite/TS/Tailwind/Vitest/ESLint
configs, `codegen.ts`, `src/` (`main.tsx`, `App.tsx`, `api/`, `components/`, `lib/`, `routes/`,
`styles/tokens.css`), and test files alongside each component.

**Cross-repo**: adds a build-time dependency on `../ksp-backend/schema.gql` by relative path.
That couples the two working trees on one developer machine, which is worth stating plainly —
it is a deliberate trade for not depending on a running server or a published package. A
missing or stale backend checkout must produce a clear error from the generate script, not a
confusing type error.

**Dependencies**: react, react-dom, react-router, @tanstack/react-query, tailwindcss, vite,
typescript, vitest, @testing-library/react, @graphql-codegen/\*, graphql,
@trivago/prettier-plugin-sort-imports, prettier, eslint.

**Conventions**: this is the change that turns `frontend.md`, `tailwind.md` and `testing.md`
from written claims into enforced practice — and the first opportunity to find out where those
documents are wrong.
